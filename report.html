    收获认知

  • 委派协议的价值被实证：42 次子 Agent 调用 + 调度者只做编排/聚合/裁决，主 Agent 上下文未爆，全程零"凭记忆写内容"——每节点内容都是子 Agent curl 直读 OI Wiki/CP-Alg 原文后撰写，这正是"调研质量决定图谱质量"的落地。
  • 子 Agent 自修复能力是质量保障：40+ 逻辑 bug 在实跑自测中被发现并修复（而非凭直觉断言正确），证明"不报告成功除非有新鲜验证证据"的纪律在子 Agent 层也生效。
  • 波次执行 + 落盘校验是容错关键：6 次批次失败（子 Agent 中途返回）都靠"磁盘状态核实 + 重跑"恢复，从未丢失已产出数据；_batch-plan.json 作为批次跟踪文件是重要基建。
  • 网络预研前置省了大量返工：CF API 不可用、OI Wiki 域名纠正、CF 403 对策，都在量产前测清，子 Agent prompt 里直接注入联网规范。
  • 质量门控要分两层：内容生成时的自验证（py_compile+实跑）+ 全量审计（字段/一致性/命名归一）——后者抓到 6 类规范化问题，若不修会污染下游 HTML 生成。

    • 过程建议

  • 子 Agent 批次失败模式：返回中途状态（"I'll create a generator script"）但未落盘的情况反复出现，建议后续在 prompt 中强化"必须先写文件再返回"（已在重跑 prompt 中加"必须写文件"强化，效果显著）。
  • 批次粒度：14 节点/批 + 6 并行/波是甜点区；过大的组（26 节点）拆开后更稳。
  • 后续构建阶段建议：基于 372 节点内容库生成 HTML 页时，直接读 stage2-nodes/*.json（数据源已规范化），模板复用 rc8 的 cytoscape 交互图 + 页内步骤 DAG；冲刺视图用 priority 字段过滤；组内连续导航用 group 字段分组排序。

    • 对未来类似任务的建议

  • 大规模内容生产任务：先小批量试点验证模板（本任务试点 9 节点），再波次量产，避免返工
  • 联网调研：先做信源可达性实测 + 并发对策，把结论注入子 Agent prompt
  • 质量门控：分"生成时自验证 + 全量审计"两层，审计报告驱动规范化修复
